# Chat RPG Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver a signed Android APK of a Korean AI text RPG with GitHub source.
**Architecture:** Bundled offline web UI and pure JavaScript game core; native Java secure storage and HTTPS bridge. AI structured turn proposals are validated before state changes.
**Tech Stack:** Java 8 source, Android SDK 35/build-tools 35, vanilla JS, Node built-in tests, Python build script.
**Spec:** docs/superpowers/specs/2026-10-02-chat-rpg-design.md

## Global Constraints
- Android minSdk26 targetSdk35; no backend or third-party runtime dependencies.
- API credentials only Android Keystore-encrypted native preferences, never JS/state/GitHub.
- Existing main branch untouched; dedicated chat-rpg branch.
- New campaigns fix demo/AI mode; failures preserve state; one request at a time.

## Review Focus
- Invalid model JSON or large/negative item quantities must not corrupt a campaign.
- Background/resume/rotation must not double-apply a turn.
- API auth, rate limit, connection timeout or refusal preserves editable action.
- Import/export excludes keys and rejects invalid or oversized saves.
- Local asset rendering must not execute arbitrary HTML or remote scripts.

### Task 2: Android shell, secure API/storage bridge and APK builder
Files: app/src/main/java/dev/ojun/chatrpg/MainActivity.java; AndroidManifest.xml; res; scripts/build-apk.py; .github/workflows/android.yml.
Interfaces: window.AndroidBridge.call(id,method,jsonArgs); callback window.NativeCallbacks.receive(id,jsonResult). Methods: configGet/configSet, request({body}), load/save({data}), export({data}), import, deleteKey. Results: {ok:true,data:<object|string|null>} or {ok:false,error:<Korean text>}. configGet returns {hasKey,model}; configSet accepts {key,model}; request posts Responses API JSON body with native credential. load/save use UTF-8 app-private file. Import/export use SAF activity results. Async bridge on dedicated executor, callbacks on UI. No secrets in error/logging. SDK builder compiles resources/java/dex, includes assets, aligns/signs with separately stored development key.
- [ ] Confirm source can compile against android.jar; verify manifest/resource links and APK signature.
- [ ] Test protocol contract and HTTP error mapping where environment allows.
